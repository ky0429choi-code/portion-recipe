# 배포 절차 — 기존 GAS 프로젝트를 v3로 교체

> **GAS 프로젝트는 하나만 씁니다.** 기존 인당량 GAS 프로젝트의 코드를 v3로 교체하고, 기존 `/exec` 주소를 그대로 GitHub Pages가 호출합니다.
> 교체 전에 현재 GAS 코드를 `backup/`에 내려받아 보관하고(깃 제외), GAS의 이전 '버전'도 남아 있어 롤백할 수 있습니다.
> `setupV3()`는 운영 DB에 `USERS`·`SESSIONS` 탭과 `CONFIG`의 `AUTH_MODE` 한 줄만 **추가**합니다(기존 탭·데이터 변경 없음).

## 교체하면 달라지는 점

| 항목 | 지금 | 교체 후 |
|---|---|---|
| 사용자가 여는 주소 | GAS `/exec` (화면이 GAS에서 열림) | **GitHub Pages 주소** |
| GAS `/exec` 주소 | 화면 제공 | 같은 주소, **데이터 API 전용** (브라우저로 열면 상태 JSON만 표시) |
| 배포 설정 | 실행: 액세스하는 사용자 / 액세스: 나만 | 실행: **나** / 액세스: **모든 사용자** (게이트는 코드가 담당) |
| 로그인 | Google 계정(본인만) | 시트의 아이디·비밀번호 (여러 명, 권한 범위별) |

## 0. 준비 (PC에 한 번)

```powershell
winget install --id Git.Git -e
winget install --id GitHub.cli -e
```

설치 후 PowerShell을 새로 열고 `git --version`, `gh --version`으로 확인합니다. Node.js와 clasp는 이미 설치되어 있습니다.
`clasp show-authorized-user`로 **GAS 프로젝트를 소유한 Google 계정**으로 로그인되어 있는지 확인합니다(다르면 `clasp login`).

## 1. 기존 프로젝트에 연결 + 백업 (업로드 없음)

1. 기존 GAS 편집기 → **프로젝트 설정 → 스크립트 ID**를 복사합니다. (`/exec` 주소 속 ID와 다릅니다)
2. 실행합니다.
   ```powershell
   .\tools\deploy-gas.ps1 -Attach -ScriptId "<스크립트 ID>" -ExecUrl "<기존 /exec 주소>"
   ```
   - 현재 GAS 코드 전체, 배포 목록, 버전 목록을 `backup/live_날짜/`에 저장합니다.
   - 입력한 `/exec` 주소가 그 프로젝트의 배포가 맞는지 확인합니다.
3. `backup/live_날짜/` 내용을 열어 지금 GAS에 실제로 무엇이 올라가 있는지 확인합니다.

## 2. 코드 교체 (사용자 화면은 아직 그대로)

```powershell
.\tools\deploy-gas.ps1
```

시험이 통과하면 `YES` 확인 후 GAS 프로젝트 파일을 v3로 교체합니다(옛 `Code.gs`, `Index.html` 등은 삭제).
기존 웹앱은 이전 버전에 고정되어 있으므로 **이 단계에서는 사용자가 보는 화면이 바뀌지 않습니다.**

## 3. 서버 설정 (GAS 편집기)

1. `clasp open-script`로 편집기를 엽니다.
2. **프로젝트 설정 → 스크립트 속성**
   | 속성 | 값 |
   |---|---|
   | `SHEET_ID` | 운영 DB 스프레드시트 ID (이미 있으면 그대로) |
   | `ADMIN_USER_ID` | 최초 관리자 아이디 (소문자) |
   - 예전 `OWNER_EMAIL`, `USE_IMPORTED_DATA`는 v3에서 쓰지 않습니다. 두거나 지워도 됩니다.
3. 함수 `setupV3` 실행 → 권한 승인 → 실행 로그 확인
4. `measureHashSpeed` 실행 → 1초를 크게 넘으면 스크립트 속성 `PBKDF2_ITER`를 낮춤(최소 1000)
5. `issueTempPasswords` 실행 → **실행 로그**에서 관리자 임시 비밀번호 확인

## 4. 화면 연결 + GitHub Pages

1. `docs/assets/js/config.js`의 `API_URL`에 **기존 `/exec` 주소**를 넣고 `node tests/run-all.js`로 확인합니다.
2. 저장소를 만들고 올립니다.
   ```powershell
   gh auth login
   git init
   git add .
   git status          # .clasp.json, tools/deploy.local.json, backup/, xlsx/csv가 목록에 없는지 확인
   git commit -m "인당량 가이드 v3: Pages 화면 + GAS 계정 게이트"
   gh repo create portion-guide --public --source . --push
   ```
3. GitHub 저장소 **Settings → Pages**: Source `Deploy from a branch`, Branch `main` / 폴더 `/docs`
4. 이 시점의 Pages 화면은 로그인 창이 뜨지만, GAS가 아직 옛 버전이라 로그인은 되지 않습니다. 정상입니다.

## 5. 웹앱 전환

```powershell
.\tools\deploy-gas.ps1 -Deploy
```

- 새 버전을 만들고 **기존 배포(같은 `/exec` 주소)** 를 그 버전으로 갱신합니다.
- 편집기 **배포 → 배포 관리**에서 이 배포가 **실행: 나 / 액세스: 모든 사용자**인지 확인합니다. 다르면 연필 아이콘 → 두 항목만 바꿔 저장합니다(주소 유지).
- Pages 주소에서 관리자 임시 비밀번호로 로그인 → 비밀번호 변경 → 메뉴·레시피 건수 확인

## 6. 이후 업데이트

| 바꾼 것 | 할 일 |
|---|---|
| 화면(`docs/`) | `node tests/run-all.js` → `git commit` → `git push` (Pages 자동 반영) |
| 서버(`gas/`) | `.\tools\deploy-gas.ps1 -Deploy` (같은 주소로 새 버전) → `git push` |

## 7. 롤백

- **서버만 되돌리기**: 편집기 **배포 관리 → 편집 → 버전**에서 교체 전 버전을 선택하고, 실행·액세스를 예전 값(액세스하는 사용자 / 나만)으로 되돌려 저장합니다. 주소는 같습니다.
- **코드까지 되돌리기**: `backup/live_날짜/`의 파일로 GAS 프로젝트를 복원합니다(필요하면 요청하세요).
- **긴급 차단**: `revokeAllSessions` 실행으로 전체 로그아웃. 또는 배포 관리에서 액세스를 '나만'으로 변경
- **화면**: `git revert <커밋>` → `git push`
