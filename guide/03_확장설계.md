# 확장 설계 — 인사이트·운영현황 연결

## 최종 목표

인당량 가이드, 웰스토리 운영현황, 운영 인사이트가 **같은 계정·같은 권한 규칙**으로 연결되어, 한 번 로그인하면 권한 범위 안에서 여러 도구의 정보를 함께 보고 인사이트를 얻는다.

## 지금 만들어 둔 연결점

| 구성 | 위치 | 확장 시 역할 |
|---|---|---|
| 계정·비밀번호 | `gas/10_Auth_Password.gs` | 공용 게이트로 그대로 이전 가능 |
| 세션 토큰 | `gas/11_Auth_Session.gs` | 도구 간 공유 토큰의 기준 |
| 권한 검사 | `gas/12_Auth_Guard.gs` (`requireSession_`, `canSeeSite_`, `requireRole_`) | 모든 도구가 같은 함수로 범위 판단 |
| 요청 규약 | `gas/90_Router.gs` | `{action, token, payload}` → `{ok, data}` / `{ok:false, code, message}` |
| 화면 호출 | `docs/assets/js/api.js` | 다른 도구 화면에서 그대로 재사용 |

## 단계안 (결정 필요)

1. **현재**: 인당량 GAS 안에 게이트 포함 (단일 도구)
2. **연결 1단계**: 계정·세션을 `공용 게이트` GAS + `공용 계정 시트`로 분리. 각 도구 GAS는 공용 게이트에 토큰 확인만 요청하거나, 같은 계정 시트를 읽기 전용으로 참조
3. **연결 2단계**: 운영현황·인사이트 데이터 API를 같은 `action` 규약으로 추가하고, 화면은 하나의 포털(탭)에서 도구를 전환
4. **인사이트**: 인당량(기준량·실제 담음량)과 운영현황(식수·손익)을 같은 사업장·기간 키로 결합. 계산은 서버에서만 수행

## 남은 결정 사항

- **레시피 범위**: 현재 통합 레시피는 지역 공용으로 보고 로그인 사용자 전체에 제공합니다. 사업장별로 제한하려면 `RECIPES`에 사업장 코드 열을 두고 `apiBootstrap_`에서 `canSeeSite_`를 적용합니다(`ownerSite`는 이름이라 코드 기준으로 쓰기 어렵습니다).
- **사업장 코드 체계**: 인당량 `siteId`, 운영현황, 인사이트의 사업장 식별자를 하나로 통일해야 결합이 가능합니다.
- **역할 세분화**: `ADMIN/USER` → 지역 관리자·사업장 담당·지원부서 등 (AI Player 설계의 지역/현장 분리 원칙 참고)
- **사내 보안 승인**: 개인 Google 계정·공개 GitHub 경로로 사내 자료를 운영해도 되는지 아직 확인되지 않았습니다.
